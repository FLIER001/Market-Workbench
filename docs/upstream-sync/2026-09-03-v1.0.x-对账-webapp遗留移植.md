## 背景：为什么只能手工移植，不能 merge

上游 2026-08-22 起从 b486522「Vibe-Research-Agent 首次提交」重写为基于 OpenAI Codex Harness
的本地金融研究 Agent（v1.0.0 = 2026-08-28，v1.0.2 = 2026-08-31）。新树只有
orchestrator/ desktop/ backtest/ calc/ .agents/ website/ datasources/ providers/ 等目录，
**backend/ 与 frontend/ 被整体删除**，与本仓库已零文件重叠（`.gitignore` / CHANGELOG /
README×2 四个共有文件全是无意义冲突）。`git merge upstream/main` 等于采纳上游树、
删掉本地全部 webapp 代码，永久不可行。Agent 线（b486522..dd89193，51 个提交）是
另一个产品形态，只可读代码借鉴，不在移植范围。

上游 webapp 线 29 个提交（37a23f8..ab4ffa0）中，v0.3.x 部分已于 2026-08-11 在
90cdf7e 全部同步（见 2026-08-11-v0.3.1-分析.md）。本次对账确认剩余未同步项共三块，
处置如下。

## 一、已移植：newsradar 条目层去重（上游 6dac1ca + 0b28982）

**上游做了什么：** 同步 investment-news v1.0.2/v1.0.3——RSS 源清单去掉 2 个跨栏重复源
（108→106，Engadget 与少数派同时挂在 tech 和 consumer 两条赛道，同一新闻抓两遍显示两张卡）；
newsradar.py 增加条目层去重：URL 归一化（剥 13 个白名单跟踪参数 + 去锚点/尾斜杠，
query 用 urlencode 重新转义防 `?id=a%26b%3Dc` 与 `?id=a&b=c` 归一化撞 key）+
标题归一化 48h 窗口去重（无发布时间不做标题去重；被丢弃条目也登记 key 保证重复关系传递；
保留条目刷新标题基准时间，防同名固定栏目跨窗口复现漏删）。

**本次移植：**
- `backend/newsradar.py`：`_TRACKING_PARAMS` / `_DUP_TITLE_WINDOW_S` / `_normalize_url` /
  `_normalize_title` / `_dedup` 整段引入；`fetch_radar()` 各赛道排序后接 `_dedup`。
  本地新闻页的 AI 提要/今日要点逻辑不在去重路径上，未受影响。
- `backend/news_sources.json`：去重 + 归属对齐上游（108→106，Engadget/少数派归
  consumer；内容与上游逐条一致，格式重排）。
- `backend/tests/test_newsradar_cache.py`：补 4 个测试（基准时间刷新、无时间戳不去重、
  urlencode 重转义、同 URL 跨源保最新）。

## 二、已评估不移植：GPU 租金信号页（上游 e45fb3e + 0b28982）

上游新增 /signals 分页（「一句话信号」栏目机制，第一期 GPU 租金三条腿：500.farm 近一年
逐日中位价、现货卡、Kalshi KXB200MS 阶梯合约远期概率），含 backend/signals.py（550 行）、
seed 快照、40 个离线测试、前端 Signals.tsx + EChart.tsx、`query_gpu_rent` AI 工具。

**处置：曾完整移植并实测通过（后端 40 测试全过、联网刷新正常、tsc/build 全绿），应用户
要求删除，不保留在本仓库。** 上游代码路径与提交号（e45fb3e 引入 / 0b28982 加固，最终态
见 ab4ffa0）已记录在此，将来若要恢复，从 `git show ab4ffa0:backend/signals.py` 等直接取

- 每次刷新需拉 100+ 张合约日 K（约 40-60s），重而收益窄。
