## 四、globalpercent：上游已删，按 Vibe-Research 审计回补

`api.github.com` 与 `git ls-remote` 均返回 "Repository not found"；GitHub 上仅有一个 2026-06-05
的无关同名仓库。上游已无补丁可拉。

继任产品 Vibe-Research 的「第 18 层宏观概率」（2026-08-24）直接移植自 globalpercent，其 CHANGELOG
记录了十轮 Codex 审计与 issue #21 的修复。据此回补三处 P1（都曾在本地副本中真实存在）：

1. **Polymarket `prob_yes` 取错腿**（`polymarket_signals._shape()`）
   `outcomes` 顺序不保证是 `["Yes","No"]`，原实现直接取 `outcomePrices[0]` —— 顺序一反过来，
   报出去的就是**方向相反的概率**，且不报错。现改为：两个数组配对、只认 Yes 腿；
   `token_id_yes` 按同一下标取（原来会画成 No 那条趋势线）；认不出 Yes 腿或长度对不上就丢弃，
   不猜。顺带修正了 `fetch_markets()` / `_shaped_polymarket()` 的调用处与类型。
2. **`Borussia` 命中 `russia`**（`market_taxonomy.classify()`）
   体育元数据优先于标题子串：Kalshi 自带 `category == "Sports"` 直接归体育；Polymarket 没有
   结构化元数据，用一份「会被国家名子串误命中」的实体清单兜底。真正的地缘政治（俄罗斯、伊朗）
   不受影响。
3. **「两个源都失败」判据**（`market_pulse._build()`）
   原判据是「有没有 item」，于是一个源报错、另一个成功但本轮没有符合条件的合约，也会被报成
   两个源都失败 —— 假事实。现改为 `asyncio.gather(..., return_exceptions=True)`，按成功的源数
   判断，报错文案逐源区分「取数失败」与「返回 0 条」。行为不变（仍不覆盖 last-good 快照）。

另：`backend/fedwatch.py` 的 Polymarket FOMC 解析有同款 `prices[0]` 取 Yes 写法，一并修正。

回归测试：`backend/tests/test_pulse.py` 新增 3 条（逆序 outcomes 的 Yes 腿与 token 配对、无 Yes
腿丢弃、Borussia/体育元数据优先级、单源失败文案）。离线全量 847 passed。

刻意未吸收（上游有但我们不需要）：

| 上游做法 | 不吸收的理由 |
| --- | --- |
| 「ask 与 last 混成同一口径」→ 记 `price_type` | 本产品不做跨合约概率比较，也不把概率当证据输出到裁决链路；多一层字段没有下游消费方 |
| `raw_ref` 逐请求绑定、`complete` 三态 | 这套是研究 Agent 的「每个数字都能追到 raw」证据链要求，本面板只做展示 |
| 每模块取前 3、成交量/持仓混合排序 | 本面板按模块分卡展示全部合约，不需要「每模块只留 3 条」的收敛 |
